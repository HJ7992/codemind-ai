# ADR 0001：外部模型 API、源码外发边界与敏感信息处理

- 状态：已接受
- 日期：2026-10-29
- 关联：[MVP 设计冻结](../mvp-design-freeze.md)、[API 契约](../api/mvp-api-contract.md)

## 1. 背景

CodeMind AI 需要 Embedding 建立向量索引，并需要 Chat 模型基于检索代码回答。用户允许必要代码片段外发，但不允许把整个 ZIP 或整个项目上传给模型提供商。上传代码还可能包含凭证，因此必须在本地先执行高置信度敏感信息检查。

## 2. 决策

### 2.1 模型服务

- 使用可配置的 OpenAI 兼容 HTTP API，Chat 与 Embedding 分别配置地址、模型、密钥和超时。
- 只有 FastAPI 服务端调用外部模型。浏览器不持有密钥，Spring Boot 不转发浏览器任意模型请求。
- 不根据浏览器参数自由选择模型、topK、检索策略或提供商。
- 模型异常返回明确错误，不伪造结果，不静默切换到未配置服务。
- MVP 不自动重试模型调用，避免重复费用；索引崩溃恢复受最大尝试次数限制。

### 2.2 数据外发

| 调用 | 允许发送 | 禁止发送 |
|---|---|---|
| Embedding | 单个/有限批量代码块；必要、最少的定位元数据 | 完整 ZIP、整个目录、未选择的所有源码、绝对路径、秘密 |
| Chat | 用户问题、必要提示词、本次检索代码片段、最少相对定位元数据 | 未检索选中的全部源码、完整 ZIP、绝对路径、秘密 |

Embedding 与 Chat 都属于代码文本外发。外部模型只提供向量或文本生成，不负责项目存储、索引状态或引用定位。引用由系统根据真实检索 payload 和源码构造。

### 2.3 隐私确认

- 前端上传前从 Spring Boot 获取隐私告知，展示当前 Chat/Embedding 地址、数据类型、用途、第三方保留政策提示和本地检测局限。
- 上传请求必须携带对应 `noticeVersion` 和明确外发确认；地址或告知版本变化后需重新确认。
- 对外展示的服务地址必须剥离用户信息、查询参数和片段，不能包含密钥。
- 为支持上传前读取服务端真实配置，新增轻量公开接口 `GET /api/v1/privacy-notice`。它只返回非敏感告知，不是通用模型代理。

### 2.4 敏感信息

- 高置信度私钥/Token 扫描在本地、任何模型请求之前完成。
- 命中即拒绝整个上传并清理临时文件，错误消息不包含秘密值。
- 不把完整源码交给云端执行秘密扫描。
- 明确承认本地规则不能保证识别所有秘密；用户需自行审查并确认第三方政策。

### 2.5 配置与日志

- 密钥只通过未跟踪环境文件或密钥管理注入，使用占位符示例。
- 密钥不进入源码、README、前端、日志、测试报告或 Git。
- 普通日志只记录提供商、模型、traceId、耗时和脱敏错误类别等必要元数据。
- 不记录完整外部请求体、完整源码、Authorization 或上游原始错误正文。

### 2.6 测试

- CI 使用确定性 Fake Embedding/Fake LLM，不访问真实模型。
- 另用本地 Mock HTTP 服务捕获实际出站请求，分别验证 Embedding 和 Chat 的边界。
- 断言请求只含允许代码块/问题，不含 ZIP、整个项目、绝对路径和已拦截秘密。
- 测试日志脱敏、上游错误脱敏、无静默回退、请求超时及配置缺失。
- 真实 API 冒烟测试显式启用，不进入离线 CI，不使用含秘密的源码。

## 3. 备选方案

| 方案 | 不采用原因 |
|---|---|
| 浏览器直接调用模型 | 暴露密钥，无法统一执行隐私和外发控制 |
| 一次性发送整个项目 | 超出必要范围，增加成本和泄漏面 |
| 只用 Chat，在问答时读取整个项目 | 无法建立可复用索引，且同样造成过度外发 |
| 云端秘密扫描 | 在检测前就已外发完整源码，违背安全目标 |
| 默认自动切换备用模型 | 可能改变外发目的地并隐瞒故障 |
| 模型生成路径和行号 | 无法保证引用真实性 |

## 4. 后果

正面：

- 外发目的地和数据范围可审查、可测试。
- Chat 与 Embedding 可独立配置，保留部署灵活性。
- 引用可信边界不依赖模型自觉。

代价：

- 上传前需要隐私告知和确认接口。
- 外部 Embedding 在索引期仍会接触所有被索引代码块，用户必须知情。
- 本地敏感信息检测存在漏报，不能替代人工审查。
- 模型故障会明确导致索引或问答失败，而不是伪装可用。
