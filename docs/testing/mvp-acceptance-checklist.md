# CodeMind AI MVP 测试验收清单

- 状态：待后续实现执行
- 上位规范：[MVP 设计冻结](../mvp-design-freeze.md)
- 说明：本清单中的复选框默认未执行。只有保留真实命令输出、测试报告或手工验收记录后才能勾选，禁止以设计完成代替测试通过。

## 1. 验收证据规则

- [ ] 每次验收记录 commit、日期、环境、配置版本、实际命令和结果。
- [ ] CI 默认离线、确定、零模型 API 成本；Fake 输出固定且可复现。
- [ ] 真实 API 冒烟测试单独标记，不与 CI 结果混合，不记录密钥和完整源码。
- [ ] 失败测试如实保留，不通过修改预期、删除样本或虚构输出制造通过。
- [ ] 性能和质量指标只在实际测量后填写，附数据集、参数与原始结果。

## 2. 任务 1：文档与契约审查

- [ ] 七项交付物存在，README 能导航到唯一规范入口。
- [ ] 旧计划已标为历史文档，不再保留“待确认”的冲突决策。
- [ ] 公开和内部每个接口均有请求、成功响应、失败响应及 HTTP 状态码。
- [ ] 所有 JSON 示例可解析；所有 UUID、字段名、时间和枚举符合通用约定。
- [ ] 所有 Markdown 相对链接可解析到存在的文件。
- [ ] 状态机覆盖成功、失败、重试、重启、删除并发和版本切换。
- [ ] MySQL/Qdrant 约束及源码外发边界无相互矛盾描述。
- [ ] `deploy/env.example` 只有占位符，实际环境文件被 Git 忽略。

## 3. API 契约测试

### 3.1 通用

- [ ] 请求未知字段返回 400，统一错误体严格为 `errorCode/message/traceId`。
- [ ] traceId 贯穿 Spring 与 FastAPI；成功响应也有 `X-Trace-Id`。
- [ ] 所有 UUID、时间、枚举、空数组和 nullable 字段符合契约。
- [ ] 内部接口无凭证/错误凭证返回 401；浏览器不能路由到内部接口。
- [ ] MySQL、Qdrant、模型地址和密钥不出现在健康检查或错误中。
- [ ] 公开 DTO、内部 DTO、数据库实体的序列化测试防止字段串用。

### 3.2 公开接口

- [ ] `GET /privacy-notice` 返回当前脱敏 Chat/Embedding 地址、用途、数据类型、版本和第三方政策提示。
- [ ] 上传缺少确认、确认不为 true、版本过期均被拒绝。
- [ ] 合法上传返回 202 和三个匹配 ID，状态为 INDEXING，不提前返回 READY。
- [ ] 项目查询在 READY 前活动版本为 null，READY 后指向任务版本。
- [ ] 任务查询计数、尝试次数、状态和脱敏错误符合契约。
- [ ] 只有 READY 项目能创建会话；INDEXING/INDEX_FAILED/DELETING 返回 409。
- [ ] 问答请求只接受 question；model/topK/strategy 等字段返回 400。
- [ ] 问答成功返回 200；失败返回非 2xx，历史失败消息不能标记 COMPLETED。
- [ ] 无证据问答返回空引用，chatModel=null，且 Mock Chat 无调用。
- [ ] 源码查看验证版本、路径、归属和闭区间行号；最多 500 行/100 KB。
- [ ] 项目 DELETE 重复执行幂等；完成后 GET 返回 404。
- [ ] Actuator 健康检查只暴露聚合 UP/DOWN。

### 3.3 内部接口

- [ ] 索引请求验证 job/project/version/storageKey；路径逃逸返回 400。
- [ ] 索引成功响应三个 ID 与请求一致，sourceFileCount/chunkCount 完整。
- [ ] 同版本并发索引返回 409；活动版本原地重建被拒绝。
- [ ] 已删除版本再次索引返回 410。
- [ ] 内部 QA 和检索始终携带 projectId/sourceVersionId，topK 仅内部检索可指定。
- [ ] 版本删除要求 projectId 归属匹配，首次和重复删除均符合契约。
- [ ] ready 检查不调用付费模型；live 不依赖外部模型。

## 4. ZIP 与上传安全

使用真实构造的 ZIP 字节样本，不仅 mock 校验函数：

- [ ] 正常 Java、Python、UTF-8 BOM、中文路径/注释样本成功。
- [ ] `../`、绝对 POSIX 路径、Windows 盘符、UNC、混合分隔符、NUL 均拒绝。
- [ ] 加密 ZIP、符号链接、重复规范化路径（含 NFC 和大小写变体）拒绝。
- [ ] 分别验证 50 MB、200 MB、10,000 条目、2 MB、深度 20、压缩比 100 的边界及刚好超限。
- [ ] ZIP 头声明很小但实际解压超限，流式累计仍能拒绝。
- [ ] 非 ZIP 或伪扩展返回 415；非白名单文件不落盘、不索引、不外发。
- [ ] 白名单文件非 UTF-8 时整个上传明确失败，无部分项目就绪。
- [ ] 没有可用源码文件时失败。
- [ ] 高置信度私钥/Token 样本在本地命中，错误不回显秘密值。
- [ ] 每种失败路径后检查临时目录和数据库，无半成品或秘密残留。
- [ ] 上传代码从未被编译、导入或执行。
- [ ] 文档和 UI 明确敏感信息检测不能保证 100% 识别。

## 5. 源码外发与模型安全

### 5.1 本地 Mock HTTP 捕获

分别启动 Mock Embedding 和 Mock Chat，捕获真实出站 HTTP 请求：

- [ ] Embedding 请求只含当前单个/有限批量代码块和允许元数据。
- [ ] Chat 请求只含用户问题、必要提示词和本次检索片段。
- [ ] 两种请求均不含完整 ZIP、整个项目、未选中的全部源码或宿主机绝对路径。
- [ ] 已拦截秘密样本没有任何模型请求；其他样本请求体不含测试秘密值。
- [ ] 浏览器网络请求中没有模型密钥，且无法经公开 API 自定义模型地址/模型。
- [ ] Chat 与 Embedding 可使用不同 baseUrl/model/key，请求分别到达正确 Mock。
- [ ] API 请求正文和响应中的源码不进入普通应用日志。

### 5.2 模型故障与元数据

- [ ] 配置缺失、地址非法、密钥缺失时明确失败，不静默切换提供商。
- [ ] 连接失败、超时、429、500、无效 JSON、空向量、向量维度错误均正确映射。
- [ ] 上游错误正文含伪造秘密/源码时，公开错误和日志仍被脱敏。
- [ ] 日志只含允许的提供商、模型、traceId、耗时和错误类别。
- [ ] Chat/Embedding 无应用内自动重试；通过 Mock 调用次数验证。
- [ ] 无检索证据时 Chat 调用次数为 0。

## 6. 解析、切块与引用正确性

- [ ] Java 类/方法、Python 类/函数 fixture 的结构边界符合预期。
- [ ] 语法错误、空文件、超长方法触发规定的降级或失败，不静默丢文件。
- [ ] CRLF、LF、Unicode、无结尾换行和 UTF-8 BOM 的行号正确。
- [ ] 相同源码版本和代码块生成稳定 chunkId/pointId。
- [ ] 每条引用自动回读原文件并断言 snippet 与闭区间行号完全一致。
- [ ] 模型输出伪造路径、行号、引用编号时，系统拒绝或按契约降级。
- [ ] 引用数组的 citationIndex 从 1 开始且连续，路径/版本归属一致。
- [ ] 失败问答不作为成功回答展示。

## 7. MySQL 与 Qdrant

### 7.1 MySQL

- [ ] 全新数据库执行迁移成功，重复启动不重复/破坏结构。
- [ ] 所有表为 InnoDB、utf8mb4，ID/时间/状态/JSON 类型符合冻结约束。
- [ ] 外键、唯一约束、检查约束和索引通过 Testcontainers 验证。
- [ ] 活动版本只能在完整索引成功事务中设置，且归属当前项目。
- [ ] 引用复合外键能定位确切 sourceVersion，非法文件/版本组合写入失败。
- [ ] 项目删除按外键顺序执行，活动版本先置空，无循环删除失败。
- [ ] relativePath/filePath 拒绝绝对路径和 `..`；引用行号检查生效。

### 7.2 Qdrant

- [ ] payload 至少含双 ID、chunkId、路径、行号、语言、文本摘要和 `record_type`。
- [ ] 所有检索同时过滤 projectId、sourceVersionId 和 code_chunk 类型。
- [ ] 两项目、两版本使用相同代码文本仍严格隔离。
- [ ] 集合维度与配置不符时就绪失败，不能写入不兼容向量。
- [ ] 重复 upsert 不产生重复有效点；部分失败不能 READY。
- [ ] 重建只清理目标双 ID 范围，其他版本点保持不变。
- [ ] 成功前点数核对；点少了/多了都失败。
- [ ] 删除墓碑不被检索命中，AI 重启后仍阻止同版本索引。

## 8. 状态机、重试与恢复

- [ ] 参数化测试所有合法/非法项目及任务状态转换。
- [ ] Embedding 超时、Qdrant 部分失败、计数不一致均不会 READY。
- [ ] AI 成功但 MySQL 提交失败后的恢复不产生重复有效点。
- [ ] PENDING/RUNNING 在 Spring 重启后按相同版本恢复，活动版本不被提前切换。
- [ ] `maxAttempts=2` 精确执行两次，包含首次与恢复；第三次不会发生。
- [ ] INDEX_FAILED 不因服务重启自动产生模型费用。
- [ ] READY/SUCCEEDED 重启后不重建。
- [ ] 只有 READY 可问答；DELETING 立即拒绝新问答和 READY 提交。
- [ ] 删除与 PENDING、RUNNING、成功提交临界点并发，最终均不能恢复索引。
- [ ] 向量、源码、业务数据三个删除阶段分别注入失败并重试。
- [ ] 删除完成后重复 DELETE、GET 和迟到索引请求均符合契约。

## 9. 前端与隐私体验

- [ ] 首次上传前展示当前模型地址、数据类型、用途、第三方保留政策和检测局限。
- [ ] 外发确认不默认勾选；配置/noticeVersion 变化后需重新确认。
- [ ] 上传、轮询、失败、无证据、回答、引用和源码查看均有组件测试。
- [ ] 模型文本和源码按纯文本/安全代码组件渲染，XSS fixture 不执行。
- [ ] 前端构建产物和浏览器存储中无 Chat/Embedding/内部服务密钥。
- [ ] 问答 HTTP 失败显示错误，不渲染成 COMPLETED 回答。

## 10. Docker 端到端验收

- [ ] 从干净卷启动真实 MySQL、Qdrant、Spring、FastAPI、React。
- [ ] 浏览器不能访问内部 FastAPI/MySQL/Qdrant 端口。
- [ ] AI 对源码卷只读，容器非 root，上传不逃逸受控目录。
- [ ] 合法 fixture 完成上传→索引→READY→提问→引用→源码核对。
- [ ] 恶意 ZIP 在 E2E 中被拒绝，临时文件清理。
- [ ] Mock Embedding/Chat 的 E2E 断言外发内容和调用次数。
- [ ] 停止模型 Mock 后索引/问答明确失败，项目不伪装成功。
- [ ] 在索引和删除阶段分别重启服务，验证恢复。
- [ ] 保存真实测试报告和关键流程截图；不写虚构性能指标。

## 11. MVP 完成判定

只有第 2～10 节适用项全部有真实通过证据，才能宣布 MVP 完成。BM25、RRF、Rerank 和检索质量提升不得提前作为 MVP 已完成成果宣传。
